# 微信 RSS 三源影子观察（隔离只读）

此工具为量子位、DeepSeek 和月之暗面 Kimi 提供**人工审核前的证据记录**，不是生产采集器。默认配置文件 `config/wechat_rss_shadow_pilots.json` 与生产使用的 `config/intelligence_sources.json` 完全独立；三源全部写为 `enabled: false`。不会修改生产数据、发布文章、提交代码、推送首页或改变 Shadow stop。

## 如何运行（经审核的验证环境）

```bash
python3 -m unittest tests.test_wechat_rss_shadow_audit -v
python3 tools/wechat_rss_shadow_audit.py --window-days 7 > shadow-day1.json
python3 tools/wechat_rss_shadow_audit.py --window-days 7 --previous-ledger shadow-day1.json > shadow-day2.json
```

这些重定向在**操作者指定的隔离路径**保存证据，命令本身仅向 stdout 输出 JSON，没有写文件的代码。不要把包含全部文章链接的观察文件加入公开生产数据仓库；可使用隔离 CI artifacts 或私有审核目录。每日独立存档上一份结果，避免滚动窗口导致旧文章消失。后续七日观察可使用显式 `--as-of` 加时间戳；开始时必须校验时区。

## 证据字段

- `sources[]`：源 ID、请求结果、接收的合法微信文章数及七日窗口内条数。错误、超时、公众号标题不匹配均保留失败状态；失败不自动降级为“没有文章”。
- `rows[]`：确定性的内部 ID、公众号、微信原文 URL、`__biz|mid|idx` 键、文章日期、首次发现/最后一次发现时间、线上同标题匹配源、待复核相似事件候选。
- `summary`：窗口内观察记录数、同标题命中数、近似标题待核查数、需要人工复核数。
- 无法靠当前 Feed 重建过去每一天的真实服务可用性或所有历史文章。七日**连续**观察必须按日独立运行七次，保存每次请求状态，并记录站长的人工核对结果。

## 发布与安全门槛

1. 独立验证环境下连续七次每日请求成功率及首次发现延迟有据可查；不以一次成功替代连续性。
2. 公众号身份、原文可访问性、文章时间、跨渠道同一事件与转载来源核查；所有候选保留人工审核。
3. 上游 RSS 托管商非公众号官方 API，不能保证完整覆盖；如果有异常或链接失效，不得自动解除隔离。
4. 对新代码进行独立 Draft PR CI 和代码审查。任何生产启用、合并或部署必须由站长明确签字，不调整安全依赖门禁。
