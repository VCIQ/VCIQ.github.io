# 科创频道：项目变化、全球投资机构与投资结果研究

## 0. 定位与本批边界

科创频道是本站重点研究工作台，不是把更多融资新闻放进一个列表。核心问题是：发生了什么变化、谁在下注、为什么下注、后续证据是否支持当时判断。

继续以技术、赛道、人物、公司为四类一级研究对象。投资机构、基金、融资事件、券商与监管披露是关联及证据层；新增 `/innovation-capital/investors/`，不再增加第五类主导航研究对象。

第一阶段已经写入开发分支的内容：

- 主频道顺序：已记录项目节点 → 拟上市储备 → 上市生命周期 → 全球重点投资机构 → 机会池/研究假设 → 上市标杆 → 政策与方法。
- 全球30家机构研究样本、官方入口、身份边界与筛选。不是全球收益排名，不宣称完整投资组合覆盖。
- 8条核验证据样例，覆盖4家机构。投资事件、观点、组合关联人、基金募集和并购结果分别记录。
- 页面明确资料版本、事件时间与采集时间不同；不使用页面构建时间冒充数据更新。
- 首页高精度内容准入：明显运势噪声和旁栏摘要不得因高分或科技标签进入公开推荐；股份变动月报不标IPO。原始档案不删除。
- GitHub只读官方页面发现脚本：每日计划检查30个已登记官方入口，输出导航候选artifact，不写公开数据或正式关系。PR只运行离线测试。该脚本不是完整组合/人物言论采集器。

尚未完成：30家逐项目组合适配、全部项目主要投资人身份归因、日常候选审核闭环、跨期投资行为统计、充分现金流支持的实际收益分析、移动端真机可视化验收、端到端生产自动回读。

## 1. 页面修改建议与验收

### 1.1 科创总览：变化优先，不再让存量数量占据首屏

推荐首屏提供最近7天/30天“已核验变化”、关注对象更新和待验证问题。无新证据时显示“最近成功检查时间；暂无新增已核验事件”，不能把抓取成功当作内容发生变化。

当前批次只从现有种子目录展示“最近记录的节点”，保留原事件日期并明确历史性质。下一阶段需增加不可变的状态变更账本，才显示旧阶段 → 新阶段。

变更记录必须有：公司ID、所属资本路径、旧状态证据、新状态证据、发生时间、披露时间、采集时间、审核时间、资料版本、原始来源、当前核验结论。一个公司可能同时有A股与港股路径，不合成一个总状态。

验收：不把旧记录包装成今日快讯；不能由当前状态猜测上一状态；同一监管公告转载十次只计一个状态变化。

### 1.2 拟上市项目：保留六家券商，但拆分角色

保持中信证券、中信建投、中金公司、国泰海通、华泰联合、广发证券。分别记录辅导、保荐、承销、历史参与角色及有效时间；不得因一篇文章同时出现公司和券商而创建合作关系。

项目卡首屏：做什么、最近变了什么、为什么值得跟踪、下一验证是什么。详细资料与完整历史进入公司主档。撤回、终止、重新辅导都保留，不只呈现成功迁移。

筛选应支持：赛道、阶段、资本路径、券商角色、事件时间、证据状态。未知上市板块保留未知，不按行业强行分类。

### 1.3 投资机构：研究名册与证据覆盖分开

当前30家为综合科技、硬科技、生命科学、区域生态的研究样本。研究分组不是法定总部或投资地域边界。不用不同年份、不同口径的AUM混排“全球前30”。

机构页应分为：投资范围与身份；已核验组合；最近行为；项目关联投资人；投资论点；结果与反例；证据覆盖和缺口。

展示三个独立覆盖指标：已登记机构数、成功适配资料入口数、具有完整项目证据的机构数。不得用30个官网HTTP200表示30家投资组合全部接通。

### 1.4 投资人发言：以项目责任证据优先，而非只关注创始人

项目负责人候选来源优先级：轮次公告明确署名 → 公司董事/观察员公告 → 机构项目页Partner关联 → 采访讨论该项目 → 一般主题发言。后两种不能自动升级成主导投资。

记录字段：人物规范ID、姓名别名、机构、发言当时职务、原始发言时间、发布平台、原文URL、页码/段落/视频时间码、逐字引语或转述、项目/轮次关联、核心判断、前提、时间范围、可证伪条件、利益关联、后续验证。

任职变动留历史，不把当前职务覆盖到旧采访。多位作者共同署名的观点不得错误归给其中一人。中文翻译标注译文，转述不加引号。

### 1.5 投资行为：区分交易单位与新闻条目

最小交易单位：机构/基金 × 公司规范ID × 轮次 × 公告/交割时间。融资总额和本机构出资额必须分列。未披露不填零，不按参投机构数均摊。

行为类别：首次投资、跟投、领投、共同领投、战略投资、二级交易、并购、基金募集、生态合作。基金募集不计入被投公司融资；组合页列名只证明目录关系，不能推断领投或支票规模。

比较维度：同一观察窗口的新投/跟投数、行业和地区迁移、投资阶段分布、合作投资网络、公开论点到实际交易的时差。窗口和可披露覆盖率必须随图表显示。

### 1.6 结果分析：先研究项目进展，再谈财务收益

项目结果分层：技术/临床验证 → 试点/付费客户/订单 → 收入与商业化 → 下一轮融资及估值条款 → 上市/并购/二级出售/清算 → 基金实际收到的现金流。

“被收购”“已上市”“估值上升”分别是不同事件，均不自动证明某机构已兑现收益。需要基金身份、投入金额和日期、持股及稀释、优先权、退出分配、费用、币种及估值口径才能计算可比IRR、MOIC、DPI、TVPI。目前纳入研究台账的项目样例尚无完整可归属基金的现金流，因此统一显示实际回报未知。

行为结果对比必须控制投资年份、阶段、赛道和观察期；说明未退出样本仍在观察、早期历史缺失，以及成功公告更易公开的幸存者偏差。不能从披露过的成功退出样本计算整家机构成功率。

### 1.7 研究输出：每次只更新被新证据影响的判断

每个研究对象保留版本化论点：原判断 → 新证据 → 支持/削弱/不相关 → 本版调整 → 下一验证。提供“与上一版比较”，不每天重写同一篇泛泛摘要。

推荐输出：每周科创变化摘要、项目证据包、机构主题迁移卡、观点—交易—结果案例、反例与未解决问题。输出不等于投资建议或自动评级。

## 2. 30家样本的选择与分批采集

完整名册见 `config/innovation_global_investors.json`。入选理由为科技研究相关性、官方组合/团队/论点材料可获取性、区域及专业范围互补。必要时按证据质量替换样本，保留版本变更原因。

建议首先深度适配有本批原文样例的Sequoia、a16z、启明、UTEC；再扩展Lux、DCVC、Eclipse、ARCH、中科创星、IQ Capital；最后扩展其余机构。这个先后是工程与研究执行顺序，不是机构优劣排名。

来源层级：监管/被投公司原文；机构官方公告/投资备忘录；明确归属的人物署名与原始音视频；可靠媒体转载。机构官方属于关联方一手来源，不能重复当成独立交叉确认。

身份边界示例：Sequoia与HongShan；Sofinnova Partners与Sofinnova Investments；Vertex SEA & India与其他区域团队；君联资本、联想创投、联想之星。别名与旧品牌按事件时间解析，不可全历史粗暴合并。

## 3. 数据与发布架构

官方发现 → 待审核证据 → 规范实体匹配 → 人工/规则核验 → 项目/人物/机构关系账本 → 构建期研究投影 → 只读公开页面。

- 浏览器只读小型投影；不在Cloudflare请求时计算30家完整组合、关系图或跨期回报。
- 定时抓取在GitHub Actions运行。当前scout单轮最多30家、并发3、单响应1MiB、单次超时8秒、重定向最多2次，先检查robots；拒绝非官方域名、凭据URL和非公开网络地址。
- blocked、robots unavailable、adapter review、no new item、success分别记录。来源失败保留上一版，但必须标明资料年龄。
- 当前scout仅从官网首页发现站内导航链接；无日期时保留null，无交易事实不建立关系。输出artifact供后续适配和审核，不直接修改投资台账或公开目录。
- 每日UTC05:43是计划时间，不是准点承诺。后续生产监控应读取实际完成及公开版本，而非只检查cron配置。
- 本批不改原Google Alerts的62个物理source，不消耗额外RSS source预算，不修改现有A/B Query与时钟。
